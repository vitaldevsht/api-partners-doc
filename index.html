Authentication model

Every protected route runs the fastify.authenticate preHandler. The JWT encodes your partner identity — partner authorization (LOGIN / EDIT / TRANSFER / PIN / EXCHANGE) is resolved server-side from the token.

!

No partner_id header.

Partner identity is managed through the Bearer token. Do not send a partner_id header on any request.

01

Partner authorizes with email + password → receives token.

02

Use that token to create & manage users.

03

User logs in with phone + PIN → access & refresh tokens + wallet.

POST /users

Create a user. Requires a JWT Bearer token (fastify.authenticate). If a wallet already exists for the phone it is linked; otherwise a new custodial wallet is created.

Headers

HeaderRequiredDescription
AuthorizationyesBearer <JWT>
Content-Typeyesapplication/json

Body — user.controller.ts:7-12

FieldTypeDescription
phonestringE.164 or local. Normalized to <phone>@vf.com if it has no @.
pinstringLogin PIN.
metadata.userobjectfirst_name, last_name.
via_apibooleantrue seeds 0.0001 HTGV + 0.0001 USDC from the service-fee wallet to the new wallet.
Minimal requestshell 
curl -X POST API_BASE_URL/users \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "50931234567",
    "pin": "1234"
  }'
With metadata + via_apishell 
curl -X POST API_BASE_URL/users \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "50931234567",
    "pin": "1234",
    "metadata": {
      "user": {
        "first_name": "Jean",
        "last_name": "Beaudry"
      }
    },
    "via_api": true
  }'

POST /api/partner/log-user

Logs a partner-initiated user session and returns a URL to redirect the user to. The init_op drives the flow: deposit returns url_deposit, withdraw returns url_withdraw. Parameters may be sent as HTTP headers or a JSON body — headers take precedence over body fields.

Parameters — header or body

NameTypeRequiredDescription
vitvit_user_idstringyes¹VitVit user UUID.
deposit_addressstringdepositExternal wallet address the user deposits to. Used for the deposit flow.
init_opstringyes¹Operation: deposit or withdraw.
amountnumber (str)yes¹Positive numeric amount. Coerced via Number().
partner_idstring (uuid)yes¹Partner identifier (UUID), e.g. 11111111-3333-....
partner_feenumber (str)noNon-negative fee, if provided.
partner_addressstringnoPartner wallet address.
Content-TypeheaderbodyMust be application/json if a body is sent.

¹ Required either as a header or as a field in the JSON body.

init_op: deposit → url_deposit
cURL — depositshell 
curl -X POST \
  https://widget.vitvit.cash/api/partner/log-user \
  -H "Content-Type: application/json" \
  -H "vitvit_user_id: 2976bc32-...a10c" \
  -H "deposit_address: 7CNGUqh8...tqsS" \
  -H "init_op: deposit" \
  -H "amount: 250" \
  -H "partner_id: 94e5300a-...b896f0" \
  -H "partner_fee: 1.5" \
  -H "partner_address: 7CNGUqh8...tqsS"
200 — Responsejson

POST /partners/:id/webhooks

Configures the webhook URL and signing secret used to deliver event notifications to a partner. The authenticated partner may only modify their own configuration — the :id path param must match the partner resolved from the token, else 403.

Path params

idPartner ID. Must match the authenticated partner.

Request body

FieldTypeConstraints
webhook_urlstringHTTPS URL to a public host (validated by isSafeWebhookUrl — rejects http://, localhost, private IP ranges).
webhook_secretstring32–256 characters. Signs outbound webhook payloads so the partner can verify authenticity.
cURL requestshell 
curl -X POST \
  https://api.vital.example/partners/PRT_123/webhooks \
  -H "Authorization: Bearer $PARTNER_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "webhook_url": "https://partner.example.com
                   /webhooks/vital",
    "webhook_secret": "0f3a...<32-256>"
  }'
200 — Responsejson 
{
  "success": true,
  "webhook": {
