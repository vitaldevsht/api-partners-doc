Authentication model

Every protected route runs the fastify.authenticate preHandler. The JWT encodes your partner identity — partner authorization (LOGIN / EDIT / TRANSFER / PIN / EXCHANGE) is resolved server-side from the token.

!

No partner_id header.

Partner identity is managed through the Bearer token. Do not send a partner_id header on any request.

01

Partner authorizes with email + password → receives token.

02

Use that token to create & manage users.

03

User logs in with phone + PIN → access & refresh tokens + wallet.

POST /users

Create a user. Requires a JWT Bearer token (fastify.authenticate). If a wallet already exists for the phone it is linked; otherwise a new custodial wallet is created.

Headers

HeaderRequiredDescription
AuthorizationyesBearer <JWT>
Content-Typeyesapplication/json

Body — user.controller.ts:7-12

FieldTypeDescription
phonestringE.164 or local. Normalized to <phone>@vf.com if it has no @.
pinstringLogin PIN.
metadata.userobjectfirst_name, last_name.
via_apibooleantrue seeds 0.0001 HTGV + 0.0001 USDC from the service-fee wallet to the new wallet.
Minimal requestshell 
curl -X POST https://dev-vital-finance-infra.vercel.app/users \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "50931234567",
    "pin": "1234"
  }'
With metadata + via_apishell 
curl -X POST https://dev-vital-finance-infra.vercel.app/users \
  -H "Authorization: Bearer $JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "50931234567",
    "pin": "1234",
    "metadata": {
      "user": {
        "first_name": "Jean",
        "last_name": "Beaudry"
      }
    },
    "via_api": true
  }'

PUT /users/:id

Update allowed fields on a user. The caller's partner identity (from the token) must carry the EDIT action in the user's allowed_partners. Protected fields are rejected.

Path params

idTarget user's ID.

Body

Non-empty JSON object. The following fields are rejected if present:

idphonepartner_idallowed_partnerswallet_idwallet_address
cURL requestshell 
curl -X PUT \
  "https://api.example.com/users/USER_ID" \

  -H "Content-Type: application/json" \
  -d '{
    "first_name": "Jean",
